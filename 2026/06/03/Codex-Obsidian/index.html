Codex + Obsidian：把 AI 协作者接进你的知识库

发表于2026-06-03|更新于2026-07-10|AIObsidian
|总字数:2.4k|阅读时长:7分钟|浏览量:

这篇文章记录一下我把 Codex 接进 Obsidian 的过程。
最终效果很简单：Obsidian 继续做我的长期知识库，Codex 则像一个可以读写 vault、整理笔记、生成文档、维护结构的 AI 协作者。

为什么要把 Codex 放进 Obsidian？🧠

Obsidian 很适合保存长期知识：读书笔记、项目资料、论文记录、灵感碎片、日记、会议纪要都可以沉淀在一个 vault 里。

但问题也很明显：笔记越多，整理成本越高。

这时候 Codex 就很适合加入进来。OpenAI 对 Codex 的定位是一个可以帮助完成真实工程任务的 coding agent，不过它不只能写代码。只要工作目录是你的 Obsidian vault，它就可以辅助处理 Markdown 文件、目录结构、索引页和项目文档。

两种连接方式

目前我理解下来，Codex + Obsidian 主要有两种玩法。

方式一：直接让 Codex 操作 vault 文件夹

这是最直接、也最稳定的方式。

以后所有让 Codex 生成的文档，都默认放到这个 Codex 文件夹里。这样好处很明显：

  • 不会打乱原有笔记结构
  • 新生成内容容易统一检查
  • 后续可以再移动到正式分类中
  • 出问题时更容易回滚或删除

这个方式不依赖 Obsidian 插件，只要 Codex 能访问你的 vault 文件夹就可以。

方式二：通过 Claudian 插件嵌入 Obsidian

另一种方式是安装 Obsidian 插件 Claudian。它的功能是把 Claude Code、Codex、Opencode 等 agent 嵌入到 Obsidian vault 里，让 vault 成为 agent 的工作目录。

插件页里提到，它支持文件读写、搜索、bash 命令、多步骤工作流、inline edit、slash commands、skills、MCP 等功能。也就是说，你可以更像在 Obsidian 里直接和一个 AI 助手协作。

下面是我的配置过程。

在 Obsidian 中配置 Codex

1. 关闭限制模式，进入第三方插件市场

打开 Obsidian 设置，进入 第三方插件，关闭安全模式或限制模式。

小提醒：第三方插件意味着插件可以在 vault 中运行代码。建议只安装自己信任的插件，并保留备份。🔐

2. 点击浏览插件市场

点击 浏览，进入 Obsidian 的社区插件市场。

3. 搜索 Claudian 并安装

搜索 Claudian，点击安装，然后启用插件。

4. 配置 Codex Provider

进入 Claudian 的设置页面，找到 Codex 相关选项，打开 Enable Codex Provider。

然后填写 Codex CLI 的路径。

如果不知道 Codex CLI 路径，可以直接在Codex里问。

如果没有看到，优先检查这几件事：

  • Obsidian 当前打开的 vault 路径是不是 Codex 正在操作的路径

2. 结合 Git 做版本管理

如果 vault 里有很多重要笔记，建议配合 Git 或 Obsidian Git 插件使用。

这样每次 Codex 批量修改之前，都可以先确认变更；如果不满意，也比较容易回退。

我的建议是：

  • 小改动可以直接让 Codex 处理
  • 大范围整理前先备份
  • 重要目录先让 Codex 给出计划
  • 批量改完后检查 diff

3. 用 Obsidian URI 打开或创建笔记

Obsidian 支持 obsidian:// URI。它可以用来打开 vault、打开文件、创建新笔记，甚至配合自动化工具使用。

使用时的注意事项 ⚠️

1. 一定要确认 vault 路径

这是最容易出错的地方。

Obsidian 里看到的 vault 名称，不一定等于你以为的文件夹路径。最好在 Obsidian 的仓库管理界面确认完整路径。

2. 给 Codex 一个专属文件夹

我现在比较推荐这样：

先让 Codex 把内容写进 Codex 文件夹，确认没问题后，再移动到正式分类。

这样既能享受 AI 协作，又不会污染原本的笔记系统。

3. 不要把敏感内容随便交给 AI

如果 vault 里有隐私信息、账号、密钥、合同、未公开项目资料，最好单独隔离。

可以采取这些做法：

  • 单独创建一个给 AI 使用的文件夹
  • 不让 Codex 读取敏感目录
  • 大范围操作前先确认计划
  • 保留备份或 Git 历史

4. 第三方插件要谨慎

Obsidian 的第三方插件很强，但也意味着插件会在本地运行。官方文档里也提到，限制模式会禁用所有社区插件。

所以安装 Claudian 这类插件时，建议确认来源、阅读说明、定期更新，并尽量只在自己信任的 vault 中使用。

总结

如果你也想把 Codex 和 Obsidian 结合起来，我建议从最简单的方式开始：

  1. 确认自己的 Obsidian vault 路径
  2. 在 vault 里新建一个 Codex 文件夹
  3. 让 Codex 只在这个文件夹里生成内容
  4. 熟悉之后再尝试 Claudian 插件
  5. 大范围修改前先备份或使用 Git
