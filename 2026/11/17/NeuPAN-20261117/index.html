NeuPAN机器人导航-论文分享

发表于2026-11-17|更新于2026-11-25|机器人路径规划
|总字数:5.6k|阅读时长:16分钟|浏览量:

这篇论文我觉得特点之一就是具体考虑了点云和障碍物之间的处理过程，不使用强化学习这种可解释性弱的方法。这篇博客，主要关注从传感器输入到控制指令的这条流程，以及 DUNE 和 NRMP 两个模块的大致处理方式。是挺有意思的。🥳

引言

本文分享的论文是 《NeuPAN: Direct Point Robot Navigation With End-to-End Model-Based Learning》，发表于 2025 年的 IEEE Transactions on Robotics。

它研究的是机器人在未知、拥挤的环境中，怎样利用传感器获得的障碍物点云，实时生成避障轨迹和控制指令。

NeuPAN 的核心思路，是用神经网络快速计算与避障相关的几何特征，再结合机器人的运动模型，通过优化求解出接下来应该怎样运动。

一、研究问题

一些导航方法会先把传感器数据转换成栅格地图、障碍物包围框或者其他几何表示，再进行规划。这样方便计算，但也可能引入额外的近似。

例如：一个凹进去的障碍物，用一个大矩形框包住以后，凹进去的空隙也被算成障碍区域。空间本来就窄的时候，这部分误差就可能影响机器人能否通过。

NeuPAN 直接利用障碍物点，并考虑机器人自身的外形，尽量保留这些几何细节。不过，点的数量一多，再加上未来多个预测时刻，计算量也会增加。论文要解决的核心矛盾就是：既保留细致的几何信息，又让规划速度满足实时控制需求。

二、整体框架

NeuPAN 是一个基于模型预测控制（MPC）的运动规划框架。MPC 会预测未来一段时间的运动，求出控制序列，并在执行一步后重新规划。NeuPAN 将点云几何计算嵌入这个过程。

📒MPC（模型预测控制）
MPC指的是一种控制方法，指的是利用机器人的运动模型，预测不同控制指令在未来产生的结果，通过优化找到最适合的一组控制指令，只执行第一步，然后根据最新观测重新规划。
➡️NeuPAN，就是在这个过程中加入了点云几何，传统的几何建模用DUNE神经网络代替，传统的MPC优化求解，用NRMP来代替。算出来的新轨迹会反馈，更新下一次的几何计算。

系统需要的输入包括：障碍物点云、机器人当前状态、机器人外形与运动模型，以及参考路径和期望速度。输出是未来一段时间的预测轨迹与控制序列；以差速机器人为例，控制量可以是线速度和角速度。

参考路径提供行进方向，避障轨迹则由规划器进一步求解。论文可用起点到终点的连线初始化路径，车辆模型还可以采用符合转向特点的路径。这里的“无地图”指不依赖预先建立的环境地图，运行时仍需要当前状态和实时传感器观测。

下面是论文的整体架构图：

图源：论文 Fig. 2，NeuPAN 从感知到控制的整体架构。

从左往右，可以分成四步：

  1. 输入与预处理：读取障碍物点云，结合预测的机器人运动，进行坐标变换，得到 Point Flows。

    point flows 指的是同一个障碍物，在未来每个预测时刻相当于机器人的位置。把所有障碍物点在未来各步的相对位置排在一起，就是送给DUNE的point flows。

  2. DUNE：将点的位置转换为潜在距离特征，也就是图中间的 Latent Distance Features。
  3. NRMP：利用这些特征，结合参考路径、期望速度和运动约束，求解新的轨迹与控制指令。
  4. 输出与反馈：输出 Trajectory 和 Actions，并将预测运动反馈给前面的模块，继续更新。

简单来说就是：DUNE 负责算几何关系，NRMP 负责规划怎样走。 图中向左的 Motion Feedback 箭头也很关键，它表示新轨迹会影响下一次几何计算。

三、DUNE 几何编码

DUNE 的全称是 Deep Unfolded Neural Encoder，深度展开神经编码器。

首先，假设机器人是一个矩形。判断障碍物会不会碰到机器人，需要考虑点到机器人外形的距离，机器人朝向变化时，这个距离也可能变化。

如果有1000障碍物点、预测10个时刻，都调用优化算法求一次几何关系，需要10000次，运行起来就会比较慢。DUNE 要做的，就是把这部分重复计算转化为训练好的网络推理。

1. 距离特征

LDF（Latent Distance Features）叫作潜在距离特征，主要涉及 μ、λ 两组变量。先看论文给出的几何解释：

图源：论文 Fig. 3，潜在距离特征的几何解释。

图中的蓝点是障碍物点，多边形表示机器人外形，红色边表示与该点最近的边界。

  • μ：与机器人哪些边界参与距离计算有关。图中红色边对应的分量可以为正，其余不相关边对应的分量为零。
  • λ：与分开机器人和障碍物点的平面的法向方向有关，可以直观理解为几何分离方向。

例如：障碍物点正对着机器人的一条边时，主要由这条边决定距离；如果点在一个角的外侧，相邻两条边都可能参与描述。

这些变量来自距离优化问题的对偶形式，也就是把原来的距离求解换成另一组等价变量来描述。结合点坐标和机器人外形，它们可以构造距离及避障表达式，因此能直接连接后面的规划器。
网络实际先输出 μ，再根据几何关系得到 λ，供后续规划使用。

要说这也是和数学这么相关的，咋我就没有这样的想法或者这样的机会来有这么的工作，如果有的话，感觉自信心会有很大的提升。

2. 深度展开

✍️这里是理解 DUNE 网络结构的重点。

传统迭代算法会从一个初始值开始，反复更新，逐步得到所需的几何变量。深度展开，就是参照这些更新步骤，把计算过程组织成神经网络层，再通过训练学习其中的参数。

论文使用的原始迭代方法叫 PIBCD。这里不用记住它的完整推导，先理解“算法更新步骤和网络层之间存在对应关系”即可。

图源：论文 Fig. 5，DUNE 的深度展开与网络层结构。图片较宽，可点击放大查看。

这张图可以分成上下两部分理解：

上半部分是迭代算法。 从左侧初始估计开始，经过第 1 次、第 2 次，直到第 J 次更新，逐步修正几何变量。图中的不同色框表示各轮更新。

下半部分是对应的网络结构。 原来的更新过程被展开为若干组网络层，最下面能看到重复出现的 FC → LN + Tanh → FC → ReLU。

图中的模块 含义 理解
FC 全连接层 对输入进行线性变换，对应迭代更新中的矩阵计算结构
LN 层归一化 调整中间特征的数值尺度
Tanh 双曲正切激活函数 对特征进行有界的非线性变换
ReLU 修正线性单元 将负值置零，与非负变量约束相联系

论文给出的设计中，隐藏层主要采用 32 个单元，展开次数取 J = 3，最终输出维度与描述机器人外形的约束数量有关。具体结构可对照论文第五节。

具体来说，为什么使用Tanh和ReLU呢，主要是因为 μ不能取负值，所以用ReLU，λ取值（-1,1），所以可以用Tanh。
看到这里，图上的 FC、Tanh、ReLU 就能和前面的几何问题联系起来了：这些层共同学习的是距离问题中的变量，随后还要把结果交给规划器使用。

DUNE 的训练数据可以利用几何求解算法生成：采样点的位置，计算对应的几何变量，再用这些结果训练网络。训练完成后，运行时通过前向推理批量处理各个点和预测时刻。它学习的是点与给定机器人外形之间的关系，因此机器人形状不变时，可以复用于不同环境。

四、NRMP 运动规划

NRMP 的全称是 Neural Regularized Motion Planner，神经正则化运动规划器。

它对应整体架构图的右半部分。拿到 DUNE 的输出以后，还要结合参考路径和机器人的运动能力，确定未来的轨迹与控制量。

例如：前方有一个箱子，绕得远一些可以增加间距，但也会偏离参考路径；速度太快，转弯可能来不及。NRMP 就是在这些要求之间进行权衡。

1. 优化目标与约束

NeuPAN 的端到端目标 由跟踪代价 和避障正则化项 组成。论文式 (13)

和 分别是预测状态序列和控制序列， 和 是前面介绍的两组距离特征。 和 分别是这两组优化变量的可行集合。

跟踪代价 累加预测窗口内的状态和速度跟踪误差。 和 是权重， 表示逐元素相乘，上标 表示参考值。论文式 (10)

避障正则化项 对每个预测时刻的各个障碍物点累加惩罚。 为负时触发安全间距惩罚， 衡量距离特征对几何等式的偏离， 和 是惩罚权重。论文式 (13)–(15)

NRMP 求解子问题 时，固定 DUNE 给出的距离特征 和 ，并加入近端项，惩罚预测状态相对上一轮迭代的变化。论文式 (26)

可以把 NRMP 的目标函数理解成下面几个部分：

组成部分 作用
路径与速度跟踪 尽量沿参考路径运动，并保持期望速度
避障正则化项 根据 DUNE 的特征，对潜在碰撞施加惩罚
近端项 限制本轮轨迹相对上一轮迭代变化过大，帮助交替优化稳定进行

此外，求解的轨迹还要满足运动学、控制量范围和控制变化幅度等约束。论文对相关非线性关系进行近似处理，使规划子问题能够利用凸优化工具求解。

例如：差速机器人不能像鼠标光标一样直接向侧面平移。规划出来的路径需要能够通过前进、转向等实际动作执行。

为了控制计算量，NRMP 还会根据预测距离筛选较近的关键障碍物点，将它们用于后续优化；安全距离则可以在设定范围内自适应调整，在空间宽裕时争取更大间距，在狭窄处兼顾通行需求。

这里的 Neural Regularized，可以理解为：神经网络输出的几何特征参与构造规划目标中的正则化项。因此，NRMP 的核心工作是实时求解优化问题。

2. 滚动控制与参数学习

NRMP 求出的控制序列按照前面介绍的 MPC 方式执行：预测未来一段时间，但每次只执行当前的第一步。

执行以后，读取新的机器人状态和传感器数据，再重新规划。

可以理解为：先往前看几步，实际走一步，再根据新情况继续算。 这样才能不断应对观测和机器人位置的变化。

论文还通过可微优化提供了部分规划参数的学习能力，例如调整跟踪权重和安全距离相关参数。这一部分称为 LON（Learnable Optimization Network，可学习优化网络）：把优化求解过程作为可微的一层，让任务表现对参数产生反馈。正常运行时，可以使用已经设置或学习好的参数，不需要每发出一次控制指令就重新训练。

五、PAN交替优化流程

回到第一张整体框架图，中间有两条方向相反的箭头：向右传递距离特征，向左反馈预测运动。

一次规划中的过程可以这样理解：

  1. 先给出预测轨迹，据此计算障碍物点在各个预测姿态下的相对位置。
  2. DUNE 更新距离特征，描述当前预测轨迹对应的几何关系。
  3. NRMP 更新轨迹和控制，综合路径跟踪、避障和运动约束进行求解。
  4. 把新轨迹传回前面，继续更新几何特征，直到满足迭代停止条件。
  5. 执行第一步控制，随后利用新观测进入下一个规划周期。

论文用 **PAN（Proximal Alternating-minimization Network，近端交替最小化网络）**来组织两个子问题的交替更新。

这里要区分两个过程：PAN 是一次规划内部的交替更新，MPC 是机器人执行动作后的滚动重规划。 把这两层关系分清，整个框架就比较容易理解了。

六、主要创新

结合前面的结构，我觉得主要可以记住三个方面：

  1. 直接利用点云进行规划。 在考虑机器人外形的同时，减少障碍物包围框等中间表示引入的几何近似，适合关注狭窄空间中的通行问题。
  2. 用深度展开加速几何计算。 DUNE 将优化算法的结构引入网络设计，输出具有几何意义的特征，帮助处理大量点与多个预测时刻带来的计算需求。
  3. 让学习与优化形成反馈。 DUNE 提供特征，NRMP 更新运动，再反馈给 DUNE；部分规划参数也能够通过学习调整。

这里的端到端体现在：系统围绕“点云输入、动作输出”建立统一的规划问题，模块间交换几何特征与预测运动，并支持通过反向传播调整参数。DUNE 与 NRMP 的分工来自同一问题的拆解，前者更新几何变量，后者更新轨迹和控制。

总结

读这篇论文，可以先抓住这条线：点云经过 DUNE 得到距离特征，NRMP 利用这些特征规划运动，再把预测运动反馈回来。

对我来说，比较有启发的是它对任务的拆分：重复、耗时的几何求解交给网络加速，运动模型和控制要求放进优化问题。这样再回头看整体框架图，神经网络为什么放在这个位置、它的输出为什么要这样设计，就更容易理解了。

扩展阅读

前面介绍了 NeuPAN 的方法，这里结合我之前整理的 Odin-Nav-Stack 笔记，看一下它在完整导航系统中的位置。

Odin-Nav-Stack 是基于 Odin1 空间感知模块构建的导航软件栈。它把建图定位、全局路径规划、实时避障和机器人控制连接起来，并将 NeuPAN 作为推荐的局部规划器。项目基于 ROS1，提供了 Unitree Go2 上的部署示例。

1. 感知与定位

首先区分两个名称：Odin1 是空间感知硬件模组，Odin-Nav-Stack 是围绕它构建的软件系统。

Odin1 集成了激光测距、RGB 摄像头和 IMU，并具备内部 SLAM 能力。它既提供图像、深度和点云等观测，也输出位姿、里程计和地图信息。仓库说明中明确指出，内部 SLAM 与重定位算法没有开源；这里主要关注它向导航栈提供的数据接口。

数据 在系统中的作用
三维点云与地图 描述环境几何，生成用于全局规划的二维栅格地图
实时点云 提取机器人附近的障碍物，供局部避障使用
位姿、Odometry 与 TF 提供位置和运动估计，并建立各坐标系之间的变换关系
RGB 图像与深度 为可选的目标识别、场景理解等功能提供输入

可以理解为：Odin1 提供“周围有什么、自己在哪里”的信息，导航软件再据此决定行进路线和控制指令。

2. 导航流程

项目推荐流程先完成建图，保存地图；再次运行时加载地图进行重定位，再接收导航目标。这里需要区分两类地图：重定位地图用于恢复机器人在环境中的位置，二维栅格地图用于全局路径搜索。

导航时，有三路信息汇入 NeuPAN：

信息来源 处理过程 交给 NeuPAN 的内容
已保存的三维点云地图 转成二维栅格地图，通过 A* 搜索并处理路径 全局参考路径
实时点云 按高度筛选并转成 LaserScan，可经 fake360 融合历史观测 局部障碍物信息
定位与里程计 通过 ROS 话题及坐标变换提供状态 当前位姿与运动反馈

NeuPAN 内部仍然由 DUNE 计算几何特征，再由 NRMP 优化运动，最终通过 /cmd_vel 输出速度指令。控制接口将这些指令接入 Unitree SDK，交给 Go2 执行。相关节点连接可对照仓库的 whole.launch。

例如：机器人从房间走到走廊尽头，A* 先根据地图给出整体路线；途中有人经过时，NeuPAN 根据实时障碍物信息调整当前运动，必要时再触发全局重规划。

这里的分工是：全局规划提供通往目标的路线，局部规划结合眼前环境决定当前怎样运动。 NeuPAN 论文本身可以不依赖先验地图，而 Odin-Nav-Stack 的这条部署流程使用了地图和全局规划器，两者对应不同层面的设计。

3. 工程适配

论文算法接入机器人以后，还要处理有限视场、控制延迟以及机器人暂时无法前进等问题。Odin-Nav-Stack 使用的是带有专门适配的 NeuPAN 分支，以下机制属于这套工程系统的实现。

fake360 障碍物记忆。 机器人转向以后，之前看见的障碍物可能离开当前视场。fake360 利用坐标变换积累历史扫描，生成供规划器使用的周向扫描，并让视场外的旧观测随时间衰减。

例如：机器人刚经过一张桌子，转头后传感器暂时看不到桌边，历史观测仍能为短时间内的转向提供参考。这里的“360”包含记忆补充的信息，不代表传感器实时看见了所有方向。

延迟补偿与脱困。 仓库加入了 Smith 预估器，考虑规划求解及执行延迟，以预测的机器人状态开始规划；当检测到持续停滞时，还可以触发重规划和脱困动作。这样，导航行为除了依赖每次优化的结果，也有处理异常状态的配套逻辑。

平台模型与参数。 以核对时的 planner.yaml 为例：

参数 配置值 含义
receding 8 MPC 预测步数
step_time 0.1 s 相邻预测时刻的时间间隔
ref_speed 0.5 m/s 期望前进速度
max_speed [0.5, 0.7] 线速度与角速度的指令限值，单位分别为 m/s、rad/s
kinematics diff 规划层采用差速运动学形式

这组配置对应约 0.8 秒的预测时域，预测时间间隔也不能直接当成系统实际控制周期。Go2 虽然是四足机器人，这里规划的是机体的平面运动，具体步态与关节执行由机器人底层控制器负责。

机器人外形变化时，需要匹配新的几何模型和 DUNE 权重，并重新调整规划参数。这些数值是该部署配置，不能直接视为 NeuPAN 论文或所有机器人的通用设置。更多工程说明见仓库调参指南。

4. 视觉功能扩展

项目还提供了目标检测、视觉语言模型和简单视觉语言导航等功能：

  • 目标检测：利用 YOLOv5 识别物体，并结合深度与坐标变换获得目标位置，支持向指定物体附近发布导航目标。
  • 场景理解：使用视觉语言模型，例如仓库示例中的 SmolVLM，生成场景的文字描述。
  • 语言交互与导航：将文字或语音意图接入上层任务流程，调用已有导航能力完成移动。

这些是可选的上层功能，基础的“地图规划 + NeuPAN 避障”流程可以独立运行。它们负责识别目标或解释任务，DUNE 则负责几何特征计算，分工各不相同。

把这个项目与论文放在一起看，可以更清楚地理解 NeuPAN 的作用：它连接了障碍物信息与运动指令；完整机器人系统还需要为它提供定位、参考路径、数据接口和执行反馈。Odin-Nav-Stack 正好展示了这些部分如何围绕局部规划器组织起来。
